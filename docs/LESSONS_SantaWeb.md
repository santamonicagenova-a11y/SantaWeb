# LESSONS — SantaWeb

Solo regole anti-errore, mai cronaca di sessione (quella è nel CHANGELOG). Riletto in apertura sessione.

- Le modifiche a `menu-admin.html` (e più in generale al pannello admin) vanno fatte direttamente sul branch `main`, non su un branch feature separato — anche quando l'harness propone di default un branch dedicato per la sessione. Se l'harness assegna un branch diverso, mergiare (fast-forward quando possibile) su `main` e pushare lì prima di chiudere il task — correzione dell'utente (2026-09-16).
- In `menu-admin.html` la versione va bumpata **in due punti**: il commento header in cima al file E il div footer visibile in UI (`<div ...>v YYYY.MM.DD.NN</div>`, in fondo al body, prima degli script di chiusura). Aggiornare solo l'header senza il footer lascia la versione mostrata in pagina disallineata — correzione dell'utente (2026-09-16).
- L'utente lavora anche da **Cowork** (desktop), dove Claude modifica i file direttamente in un clone locale (es. `D:\Temp\tmp\progetti IA\santamonica\_archivio-export\SantaWeb`) e l'utente fa il commit/push su `main` da lì. Le sessioni **cloud/remote** (come questa) girano invece in un container isolato senza accesso al filesystem dell'utente: lavorano su un proprio clone e pushano direttamente su GitHub. Le due modalità non richiedono sincronizzazione manuale di file: bastano `git pull`/`git push` sullo stesso repo — dopo un push da una sessione cloud, in Cowork è sufficiente un `git pull origin main` per riallinearsi, e viceversa (chiarito dall'utente il 2026-09-16).
